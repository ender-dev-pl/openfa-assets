# Sci-Tek Anti-Virus Missile — research 03

Actual bindings: PM08.256 and its 60-frame colour preview, ST03.VID information and ENGLISH.TXT records 1354–1356. The reference captions identify four anti-viral payload pods, four main rocket thrusters and the nose's navigational sensor/guidance assembly. Static, eighteen spaced colour phases and all nine caption anchors were inspected. Private original pixels are not imported textures.

All nineteen meshes from sources/docs/assets/reconstruction/missiles/terran/anti-virus/model.blend are reused with identical vertices, faces/material assignments, UVs, local transforms and authored materials. Original SHA256: 83795063d7b9bfb688abd34e13a0b054a702fb82eabf5800db09e4a3abb84283. No wear modernization is applied to this existing model. AntiVirusRotor applies a presentation-only transverse scale [0.83,0.83,1] to match the inspected silhouette. Do not discard this scale or apply it twice. The original source file remains unchanged.

Four technical groups: chassis, anti-viral-payload-pods, four-main-rocket-thrusters, nose-navigation-assembly. The continuous casing is not cut: technical wire edges above the upper neck joint (local Z >= 4.3999) are assigned to the nose assembly. This is a display-only semantic partition. Payload group contains four complete pods; engine group has four hollow nozzles plus their recessed throats. Nose includes the upper casing segment, neck joint, pale collar, red cap and antenna.

Colour motion is a 60-frame/15fps axial rotation of AntiVirusRotor with loop closure at Blender frame 61. Use the exact solid_preview_camera and solid_framing metadata. Unlike the wider research items, the native tile canvas is 80×160; its original drawn box is (25,16)..(55,147). Normal, disabled and 4× tiles preserve the aspect and alpha.

The separate 423-frame/15fps information Blend/GLB and information-timeline.json include all three source-caption windows: payload 29..139, thrusters 170..280, nose 311..421 (zero based). Apply timeline root rotation by replacement, retain root scale [0.83,0.83,1], and apply camera pose, orthographic scale and explicit red/green material selection. glTF alone does not portably carry material hue or orthographic scale animation. Camera/pose reconstruction is authored from the reference anchors, not recovered original 3D camera data.

Validation covers all original mesh signatures, closed topology, exact technical-wire endpoint correspondence with source vertices, source-file preservation, four pods/four nozzles, root scale and clip targets, all sixty projected poses, loop closure, all static variants and independent animation poses, complete information rendering/import/reload and full movie encode/decode. Source-framing comparison is a coarse occupancy check and is not pixel-exact fidelity acceptance. Main game thread must perform actual OpenFA runtime/GPU integration checks.

Build in Blender using build_anti_virus.py -- OUTPUT --base-blend BASE_BLEND, with geometry.py alongside it. render_preview.py and animate_information.py take INPUT_BLEND OUTPUT. --keyframes-only is a review subset, not delivery. Geometry/pose/state checks run in Blender. Device/raster/information/framing checks require Python/Pillow/FFmpeg; framing also needs private original-codec ST03 frames.
